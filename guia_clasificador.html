— Abstract

Un sistema de aprendizaje supervisado que clasifica automáticamente correos electrónicos universitarios en siete categorías. Construido sobre un dataset de 1.000 correos generados con el contexto real de la Institución Universitaria Pascual Bravo, alcanza 99.9 % de precisión en validación cruzada y se sirve a través de una API REST lista para producción.

TF-IDF Logistic Regression FastAPI scikit-learn Python 3.10+ REST API N-gramas
§ 01 / Contexto

El problema

Por qué un estudiante necesita un clasificador de correos.

La bandeja institucional de un estudiante recibe en promedio entre 40 y 100 correos por semana: tareas de Moodle, notas publicadas en SICAU, comunicados de rectoría, eventos académicos, becas, intercambios, recordatorios.

El correo de una convocatoria de intercambio en Alemania tiene la misma prioridad visual que el aviso del nuevo menú de la cafetería. Las oportunidades importantes —becas, movilidad académica, premios— se pierden entre el ruido. Este sistema aprende a separar señal de ruido y a etiquetar cada correo con una de siete categorías.

§ 02 / Datos

El dataset

Mil correos sintéticos del Pascual Bravo, etiquetados a mano.

El dataset contiene 1.000 correos generados a partir de plantillas reales del Pascual Bravo: 24 materias de Ingeniería de Sistemas, Mecánica, Eléctrica, Diseño Industrial; 20 nombres de docentes; plataformas reales (Moodle, SICAU, Microsoft Teams); oficinas institucionales (Internacionalización, Bienestar, Registro y Control).

Cada correo contiene asunto + cuerpo en formato natural, con números variables (fechas, grupos, talleres, plazos), simulando la realidad de una bandeja universitaria. La distribución intencionalmente refleja la frecuencia natural — más tareas y anuncios, menos logros.

Nota sobre datos sintéticos. El dataset se construyó programáticamente combinando plantillas con valores aleatorios (profesores, materias, fechas, plazos). Esto permite balancear las clases, pero introduce regularidad estadística que sobreestima la precisión real. En producción con correos del mundo real, esperaría una caída a 85 – 95 %.
§ 03 / Sistema

La arquitectura

Pipeline supervisado en cinco etapas, end-to-end.

Cada correo recorre un pipeline de cinco etapas: limpieza, vectorización, clasificación, regla de negocio y respuesta estructurada. Las primeras tres son scikit-learn; la cuarta es lógica explícita; la quinta vive detrás de FastAPI.

¿Por qué TF-IDF + Logística? Para un dataset de mil correos en español, los modelos lineales con representaciones bag-of-words son imbatibles en relación esfuerzo/beneficio. Un BERT en español daría ganancias marginales, costaría ~600× más en cómputo y haría la inferencia más lenta. Empezar simple es ingeniería; añadir complejidad sin justificación es vanidad.

La regla de negocio sobre intercambio existe porque es la categoría más valiosa del estudiante (oportunidades únicas) y la más fácil de detectar por palabras clave. Combinar reglas con modelos es buena práctica cuando hay conocimiento de dominio explotable.

§ 07 / Implementación

El código

Fragmentos clave del entrenamiento y la inferencia.

Tres piezas centrales: el limpiador de texto, el pipeline TF-IDF + logística, y la función de clasificación con regla de negocio. 

def limpiar_texto(texto: str) -> str:
    """Normaliza un correo eliminando ruido."""
    if not isinstance(texto, str):
        return ""
    texto = texto.lower()
    texto = re.sub(r"http\S+|www\S+", " ", texto)   # URLs
    texto = re.sub(r"\S+@\S+", " ", texto)          # emails
    texto = re.sub(r"[^a-záéíóúñü\s]", " ", texto)  # solo letras
    texto = re.sub(r"\s+", " ", texto).strip()
    return texto
pipeline = Pipeline([
    ("tfidf", TfidfVectorizer(
        ngram_range=(1, 2),       # unigramas + bigramas
        max_features=10000,
        min_df=2,
        max_df=0.85,
        sublinear_tf=True,
        stop_words=STOPWORDS_ES,
    )),
    ("modelo", LogisticRegression(
        max_iter=2000,
        C=1.0,
        class_weight="balanced",   # maneja desbalance
        random_state=42,
    )),
])
pipeline.fit(X_train, y_train)
def clasificar_correo(texto, pipeline, umbral=0.20):
    texto_limpio = limpiar_texto(texto)
    prob = pipeline.predict_proba([texto_limpio])[0]
    probs = dict(zip(pipeline.classes_, prob))

    # Regla: palabras clave fuertes → fuerza intercambio
    for palabra in PALABRAS_INTERCAMBIO:
        if palabra in texto.lower():
            if probs.get("intercambio", 0) >= umbral:
                return {"categoria": "intercambio",
                        "metodo": "regla + modelo", ...}

    categoria = max(probs, key=probs.get)
    return {"categoria": categoria, "metodo": "modelo", ...}

El código completo del proyecto incluye además: dataset generado programáticamente, script de entrenamiento con validación cruzada y comparación de modelos, API FastAPI con esquemas Pydantic, y serialización del pipeline con joblib.
